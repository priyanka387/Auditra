# Audit V1 (AI Model Inventory → Audit) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Append-only PostgreSQL audit event trail for AI Model Inventory material changes, with read-only query API, same-transaction persistence, actor/source attribution, and sanitized before/after state.

**Architecture:** New `app/modules/audit` module (models/repository/service/sanitization/schemas/routes/errors/enums) following the flat module convention used by `model_usage`/`model_discovery`. Domain services (`ModelService`, `DeploymentService`, `DeploymentEndpointService`, `DiscoveryService`) call `AuditService.record_event(...)` on their existing `db` session **before** their existing `commit(db)` — one transaction, rollback together. The existing post-commit in-process `dispatch_event` mechanism is left untouched (it is a telemetry notification bus, not transactional).

**Tech Stack:** Python 3.11+, FastAPI, SQLAlchemy 2.0 typed mappings, Alembic, PostgreSQL 16 (Docker, port 5433), pytest, uv, ruff.

**Spec:** `subfeature.md` (repo root). The plan argues from the spec; executors read both.

## Global Constraints

- Backend only. No frontend code. (spec §75 Rule 3)
- No Redis, RustFS, Kafka, queues, or new databases. (§75 Rule 5)
- No audit mutation HTTP endpoints (GET only). (§61)
- Event names: lowercase dot-delimited `<resource>.<action>`, stored as strings, never enum names like `MODEL_CREATED`. (§8)
- All timestamps timezone-aware UTC. (§14)
- Audit append and domain mutation share one transaction; audit failure rolls back the mutation. (§22, §23-B)
- Sanitization is centralized in `app/modules/audit/sanitization.py`; no ad-hoc redaction in endpoints. (§17.1)
- No hard FK from `audit_events.resource_id` to domain tables. (§27)
- Reuse existing conventions: `tenant_id` + `settings.default_tenant_id`, `DomainError` envelope, offset pagination `{items,page,page_size,total,total_pages}`, `X-Request-ID` middleware, module layout. (§55)
- Runtime: `uv` isolated env (`uv sync`, `uv run ...`); DB: `docker compose up -d` (postgres:16-alpine, host port 5433).
- Lint: `uv run ruff check .` and `uv run ruff format .` from `backend/`. Tests: `uv run pytest -v`.
- Commit per task, message style `feat(ai-inventory): ...` / `test: ...` / `docs: ...` (repo convention).

## Design decisions (Phase 1 — repository-dependent, locked)

1. **Registration semantics = decision B for manual flow.** `POST /models` → `ModelService.register_model` is a single create-and-register operation → emit only `model.created` (spec §7.2/§19: do not duplicate). `DiscoveryService.register` is a distinct domain transition (discovery status → REGISTERED, model promoted from candidate) → emit `model.created` (via ModelService) **plus** `model.registered` with `metadata.registration_mode = "discovered_then_registered"`.
2. **Event taxonomy (V1):** `model.created`, `model.registered`, `model.updated` (incl. archive → `changed_fields=["lifecycle_state"]`), `deployment.created`, `deployment.updated`, `deployment.status_changed`, `deployment.archived`, `deployment_endpoint.created`, `deployment_endpoint.updated`, `deployment_endpoint.archived`. Omitted: `deployment.environment_changed` (environment immutable after create in this domain → dead event); generic `deployment.changed` not needed (domain operations classify cleanly).
3. **Integration point:** direct `AuditService` calls in domain services before `commit` — NOT the existing `dispatch_event` handlers (they run post-commit with no session; hooking them breaks §22).
4. **Actor:** no IAM exists. `ActorContext(type, id)` built from the existing `actor: str | None` service param: non-None → `type="user", id=actor`; None → `type="system", id=None`. Tests inject actor via service constructors. No fabricated identities.
5. **Source:** `source: str = "api"` constructor param on the four auditing services (V1 callers all HTTP routes); strings, not DB enums. Extensible to `sdk`/`langgraph`/connectors later.
6. **Request context:** `request_id` from existing middleware (already threaded into services). `correlation_id` column + filter exist but stay NULL (no producer). `trace_id`/`span_id` columns omitted (no OpenTelemetry in repo) — documented deviation §13.
7. **Pagination:** offset `page`/`page_size` (default 50, max 200) with repo envelope — NOT cursor. Spec §34/§60 explicitly permits reusing the repo's offset standard; documented deviation from ADR-10.
8. **Authorization:** no auth framework exists anywhere in repo. Single extension point: `get_audit_reader()` dependency on both audit routes (no-op today; future RBAC enforces `ai_inventory.audit.read` there). 401/403 tests not possible — documented.
9. **Events not audited (scope):** model versions, applications, agents, usage, discovery ingest/ignore/match — out of §4.1 scope. Infrastructure accepts `resource_type=model_version` later without schema change.
10. **IDs:** `resource_id`/`actor_id` are `VARCHAR` strings (ADR-04); `id`/`tenant_id` UUID per repo convention.

## Review Focus

- *No-op update must emit no event* — model service computes `changed`; audit guarded on `if changed` — pinned by `test_noop_update_emits_no_audit_event`.
- *Audit failure rolls back domain mutation* — record before commit; pinned by `test_audit_failure_rolls_back_model_creation` (monkeypatch `AuditService.record_event` to raise → 500 → no model, no audit row).
- *Secrets never persisted* — centralized sanitizer; pinned by `test_sanitization_redacts_secret_keys` + `test_endpoint_auth_reference_redacted_in_audit_state`.
- *Deterministic ordering + tenant isolation* — `sequence_no DESC` within `tenant_id`; pinned by `test_list_events_orders_by_sequence_desc` and `test_list_events_scoped_to_tenant`.
- *No audit mutation routes* — pinned by `test_audit_mutation_methods_not_allowed` (POST/PUT/PATCH/DELETE → 405).
